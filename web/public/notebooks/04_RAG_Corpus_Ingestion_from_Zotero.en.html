🗂️ Notebook 04: RAG Corpus Ingestion — Folder Drop and Zotero Library

📌 Objectives:

  1. Document the two ingestion lanes feeding rag_documents and rag_chunks: dropping files into a watched directory, and ingesting directly from a local Zotero reference-manager library.
  2. Demonstrate the multi-stage deduplication hierarchy (binary MD5 → DOI → normalised header hash) and illustrate why a binary MD5 hash is insufficient once a publisher watermark has been appended during re-downloading.
  3. Establish the source-provenance ranking that prevents low-confidence metadata (inferred heuristically from PDF text) from overwriting authoritative bibliographic sources (Crossref API records or human-curated Zotero entries).
  4. Document the chunking and embedding protocol, detailing a real operational failure and its resolution (NUL bytes originating from corrupted PDF font tables) and explaining why the processing pipeline is fully resumable.
  5. Verify end-to-end performance by executing a hybrid retrieval query against the production corpus.

Source Code

This notebook narrates and invokes the production scripts without reimplementing their core logic:

  • src/rag_catalog_corpus.py — Catalogues documents into rag_documents (via watched folders and Zotero library access).
  • src/rag_zotero.py — Reads a local Zotero zotero.sqlite database and storage/ directory in a strictly read-only mode.

🗃️ Step 2: Reading a Zotero Library without Write Access

src/rag_zotero.py accesses the zotero.sqlite SQLite database and the associated storage/ directory maintained on disk by a desktop Zotero installation. Two critical safety measures are implemented:

  • The SQLite database is copied to a temporary file prior to opening. Desktop Zotero acquires an exclusive file lock while running, causing direct read operations against the active database to fail.
  • Two text sources are evaluated in hierarchical order: the original PDF file stored on disk (which also provides page and embedded image counts), falling back to Zotero's internal .zotero-ft-cache text extraction cache (retaining the plain text extracted during the last instance the PDF resided on disk). In this library, the majority of records had their bibliographic metadata synchronised without local PDF storage; without the secondary text cache fallback, most items would have been unusable.

Excluded Collections Rationale

A personal Zotero database rarely focuses exclusively on the thematic domain of a specific RAG corpus. The laboratory library examined here also hosted a dental systematic review and a fitness archive, neither of which belongs within a materials chemistry RAG system. The exclusion filter is defined within src/rag_catalog_corpus.py as EXCLUDED_COLLECTIONS_DEFAULT.

🧬 Step 3: The Multi-Stage Deduplication Hierarchy

A file's binary MD5 hash provides an exact fingerprint of its raw byte stream, but a poor fingerprint of the scientific paper it encapsulates. Academic publishers routinely append dynamic download watermarks (stamping download timestamps, IP addresses, and user identifiers) onto each page of a PDF. Consequently, an identical article downloaded from two separate sources—such as a publisher portal and an academic collaborator—yields two divergent files with distinct binary hashes.

This behaviour was demonstrated experimentally: adding an arbitrary watermark to a publication within this corpus altered both the binary MD5 hash and the MD5 hash of the extracted plain text, because the watermark text is embedded directly within the PDF body and propagates into downstream text extraction.

🏷️ Step 4: Cataloguing & Source-Provenance Ranking

src/rag_catalog_corpus.py extracts document titles, author lists, publication years, journal venues, and DOIs, committing a single record per document into rag_documents. Two distinct ingestion lanes populate this table:

  • Watched Folder Lane: Dropping a PDF, DOCX, TXT, or MD file into data/rag_corpus/{public,internal}/. Metadata is inferred from document text and optionally enriched via the public Crossref API (only DOIs of files located within the public/ directory are ever transmitted to external endpoints).
  • Zotero Library Lane: zotero_records() ingests records from the local library as described above, treating the metadata as human-curated.

An operational regression occurred here: executing a secondary ingestion pass over an already-catalogued PDF (omitting the --crossref flag) parsed only a single author from the PDF internal metadata (where publishers often record only the corresponding author). A simple COALESCE statement allowed this single-author record to overwrite the complete, nine-author list previously obtained from Crossref. To resolve this, rag_source_rank() enforces an explicit provenance hierarchy: a lower-ranked metadata source is barred from overwriting data provided by a higher-ranked source.

✂️ Step 5: Chunking & Vector Embedding

src/rag_ingest_chunks.py iterates over catalogued documents, partitioning each text into overlapping chunks (chunkSize 1200 / overlap 250, representing ≈20% overlap; dense technical prose demands higher overlap ratios than general literature to prevent boundary truncations from destroying scientific context across adjacent chunks). Each chunk is embedded using a local Ollama instance (bge-m3, yielding 1024-dimensional dense vectors) and written to rag_chunks.

During an initial overnight batch run across 947 documents, three records failed with the following database exception:

A string literal cannot contain NUL (0x00) characters.

Certain PDF text extraction engines emit NUL control bytes when encountering corrupted font encoding tables, which PostgreSQL strictly rejects within TEXT columns. The parser was updated to sanitize NUL bytes and standard C0 control characters prior to chunking. Because the pipeline is designed to be resumable—processing exclusively WHERE n_chunks = 0—re-executing the batch script after deploying the patch processed only the 3 failed documents rather than recomputing all 947.

🔍 Step 6: End-to-End Verification via Hybrid Search

src/rag_query.py executes the identical hybrid retrieval function (rag_hybrid_search(), combining dense vector similarity with lexical tsvector matching fused via Reciprocal Rank Fusion) utilised by the n8n agent's search_documentation tool. It deliberately avoids calling an LLM: if the target passage is absent from the ranked retrieval set, no downstream generative model could synthesise a grounded answer. Decoupling retrieval from generation isolates document retrieval failures from generative hallucination.
